# 봉누도2 VOD 수집 범위 및 정책

> 상태: 등록일 기반 Collector 구현 기준 (2026-09-27)
>
> 이 문서는 수집 기준을 정의할 뿐, Collector, Redis snapshot, GitHub Actions, `/vods`, 참가자 데이터는 변경하지 않는다.

실제 API 응답 구조, GTA V 단건 검증, 썸네일과 페이지네이션 관측은 [CHZZK 웹 VOD 수집 PoC](./chzzk-web-vod-poc.md)를 기준으로 한다.

## 결론

최종 VOD 목록에는 다음을 모두 만족하는 등록 기반 항목만 저장한다.

1. `getParticipants()`가 반환하는 현재 참가자의 `channelId`와 VOD의 `channelId`가 일치한다.
2. `videoType === "REPLAY"`이다.
3. `videoCategoryValue === "Grand Theft Auto V"`이다. 제목, 태그, 설명은 판별에 사용하지 않는다.
4. `publishDateAt`이 봉누도2 수집 기간에 포함된다.

`publishDateAt`은 VOD 등록 시각이다. 이 Collector는 `liveOpenDate`, `duration`, 방송 운영 시간 및 금요일 휴무를 필터링에 사용하지 않는다. 위 네 조건을 만족한 항목은 **등록 기간 기준 후보 VOD**로 보존하며, 실제 방송일을 추정해 제외하지 않는다.

## 공식 운영 기간

모든 시각 계산은 `Asia/Seoul`을 사용한다.

| 구분 | 값 |
| - | - |
| 최초 운영 창 | 2026-09-14 18:00부터 |
| 마지막 운영일 | 2026-10-04 |
| 최종 운영 창 종료 | 2026-10-05 03:00 |
| 수집 종료 | 2026-10-07 03:00 (최종 종료 뒤 2일의 등록 여유) |
| 일일 운영 창 | 운영일 18:00부터 다음 날 03:00까지 |
| 휴무 | 매주 금요일: 2026-09-18, 2026-09-25, 2026-10-02 |

기존 `getBongnudoScheduleStatus(date)`의 자정 귀속과 금요일 휴무 규칙은 Discovery에서 계속 사용한다. 이번 Collector는 등록일만 필터링하므로 이 함수를 호출하지 않는다.

## 등록일 기준

수집 범위는 KST `2026-09-14 18:00` 이상, KST `2026-10-07 03:00` 미만의 반열린 구간이다. 최종 운영 창 종료 뒤 2일의 여유를 두어 마지막 날 방송이 다음 날 등록되는 경우를 포함한다. 실제 방송 시작·종료 시각 검증은 이번 Collector 범위에서 제외한다.

## 늦게 등록되는 VOD

두 기간은 의도적으로 분리한다.

| 구분 | 기준 | 용도 |
| - | - | - |
| 공식 운영 기간 | 2026-09-14 18:00 ~ 2026-10-05 03:00 KST | 행사 기준 |
| 수집 기간 | 2026-09-14 18:00 이상 ~ 2026-10-07 03:00 미만 KST | 등록된 VOD 필터 기준 |

예를 들어 10월 4일 방송이 10월 6일 등록되면 수집 기간 안에 포함한다. 2일 이후의 추가 여유는 이번 구현에서 두지 않는다.

등록일 이전을 만났다는 이유만으로 페이지 탐색을 멈추지 않는다. 등록일은 최종 방송일 판정 기준이 아니며 늦은 등록과 정렬 변경을 모두 배제할 수 없기 때문이다.

## 페이지네이션과 증분 수집 정책

| 상황 | 정책 |
| - | - |
| 페이지 탐색 | 현재 `getParticipants()`의 각 유효 채널에 대해 API가 알린 마지막 페이지까지 읽는다. 기간 이전 `publishDateAt`을 발견해도 즉시 중단하지 않는다. |
| 중복 | `videoNo`로 upsert/dedupe한다. 이미 본 ID는 페이지 종료 근거가 아니다. |
| 정상 빈 목록 | `page: 0`, `totalPages: 0`, 빈 `data`는 성공으로 기록한다. |
| 실패 | 네트워크, 비정상 HTTP, 파싱/스키마 오류는 채널 실패로 기록하고 기존 확정 snapshot을 보존한다. |

현재 수동 Collector는 모든 페이지를 읽는다. 날짜·정렬·known ID만으로 중단하는 최적화는 추가 관측으로 안전성이 확인되기 전까지 적용하지 않는다.

## 저장 정책

기존 Redis snapshot의 실패 시 이전 값 보존, 활성 참가자 채널 정리, `videoNo` upsert 구조는 재사용한다. 확정 VOD에는 최소 다음을 보존한다.

- `videoNo`, `channelId`, 제목, 썸네일 URL, 등록일, 재생 시간, `videoType`
- `videoCategory`, `videoCategoryValue`; 원본 URL은 `videoNo`로부터 `https://chzzk.naver.com/video/{videoNo}` 형식으로 구성한다.

영상 파일과 썸네일 파일은 저장하지 않는다. 사용자는 원본 `https://chzzk.naver.com/video/{videoNo}`로 이동한다.

## 이번 Collector 구현 범위

1. 목록 mapper/model에 카테고리 원본값을 보존하고, `REPLAY`·정확한 GTA V 카테고리·등록 기간을 최종 필터로 적용한다.
2. `publishDateAt`의 KST 시작·종료 경계, 모든 페이지 탐색, `videoNo` 중복 제거, malformed 응답과 batch/snapshot 실패 보존을 테스트한다.
3. 상세 응답의 `liveOpenDate`와 `duration`은 운영 시간 필터에 사용하지 않는다. 2026-09-30 PoC는 `duration`의 초 단위 및 등록 시각과의 상관관계만 재현했고, 실제 방송 전체 구간이라는 독립 근거는 확보하지 못했다.

## 운영 고려사항

실제 자동 수집 전에는 NAVER 및 CHZZK의 관련 정책과 데이터 이용 허용 범위를 확인한다.
